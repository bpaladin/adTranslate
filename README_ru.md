# PDF Translator v1.1

Параллельный перевод PDF-документов на другой язык с сохранением форматирования, изображений и таблиц. Поддерживает режим перевода и генерации рефератов.

## Установка

```bash
pip install -r requirements.txt
```

Зависимости: `pymupdf`, `openai`, `requests`, `jinja2`, `tqdm`, `markdown`, `cachetools`.

## Быстрый старт

```bash
# Перевод через Google (без ключа)
python main.py paper.pdf

# Перевод через OpenRouter
python main.py paper.pdf -t openrouter

# Локальный переводчик (llama.cpp)
python main.py paper.pdf -t llama

# Реферат статьи
python main.py paper.pdf --summary
```

Выходной HTML-файл создаётся автоматически: `*_translate.html` или `*_summary.html`.

## Алгоритм выделения блоков для перевода

Обработка PDF-документа состоит из 5 этапов.

### Этап 1. Извлечение данных из PDF

Используется библиотека **PyMuPDF** (`fitz`). Два режима извлечения:

- **Стандартный** -- `page.get_text("dict")` извлекает блоки, линии и спаны с информацией о шрифте, размере, цвете и координатах.
- **Через pymupdf_layout** (если установлен) -- анализ макета страницы.

Каждый элемент представляет иерархию:

```
Block -> Line -> Span
  |        |      - text
  |        |      - font (имя шрифта)
  |        |      - size (размер в пунктах)
  |        |      - flags (битовые флаги: 2^0=жирный, 2^1=курсив)
  |        |      - bbox (координаты прямоугольника)
  |        - bbox
  |        - y0 (вертикальная позиция)
  - type ("text")
  - bbox
  - page_num
```

Область извлечения ограничена обрезкой верхней (40 px) и нижней (45 px) частей страницы для исключения колонтитулов и нумерации.

### Этап 2. Извлечение таблиц, изображений и векторных фигур

Параллельно с текстом извлекаются:

| Тип | Метод | Условие |
|-----|-------|---------|
| Таблица (PyMuPDF) | `page.find_tables()` | Структурированные таблицы с линиями |
| Текстовая таблица | `_find_span_table_blocks()` | Блоки с выровненными колонками (толерантность 8-10 px) |
| Растровое изображение | `page.get_images()` | Площадь > 300 px^2 |
| Векторная фигура | `page.get_drawings()` | Кластер прямоугольников, площадь > 1500 px^2 |

**Определение подписей:**

- `_is_table_caption()` -- текст начинается с "Table", "Таблица" и длина <= 120 символов
- `_is_figure_caption()` -- текст начинается с "Fig.", "Рис.", "Схема" и не содержит глаголы (illustrates, shows, depicts)

### Этап 3. Классификация текстовых блоков

Класс `BlockClassifier` определяет тип каждого текстового блока по метрикам.

**Метрики блока** (функция `block_metrics()`):

- `max_font` -- максимальный размер шрифта в блоке
- `all_upper` -- все ли символы прописные
- `has_bold` -- есть ли жирный шрифт (флаг `2^0`)
- `is_centered` -- центрирован ли блок относительно страницы (отклонение < 10% ширины)

**Логика классификации:**

1. Если нет текста или только цифры/символы -> `"empty"`
2. Если текст совпадает с заголовком раздела "References" -> `"reference_heading"`
3. Если текст -- подпись таблицы ("Table N...") -> `"table"`
4. Если слов <= 8:
   - Если это ссылка `[N]` -> `"reference"`
   - Если есть формат "Фамилия И.О." -> `"metadata"`
   - Если есть слова Journal/Volume/DOI/ISSN -> `"metadata"`
5. Если >= 2 строк-элементов списка (маркированные/нумерованные) -> `"list"`
6. Вычисление **оценки** (score):
   - `max_font > средний * 1.2` -> +3
   - Все прописные -> +2
   - Есть жирный -> +2
   - Центрирован -> +1
   - Текст < 80 символов -> +1
   - Начинается с нумерации "N.N.N" -> +2
7. Если score >= 5 -> `"heading"`, иначе -> `"paragraph"`

### Этап 4. Пост-обработка

**4.1 Разделение reference_heading.** Если блок "References" содержит продолжение текста после заголовка, он разделяется на отдельные блоки: заголовок и ссылки.

**4.2 Пометка блоков после References.** Все блоки после заголовка "References" (кроме figure/table) получают тип `"reference"`.

**4.3 Консолидация таблиц** (`consolidate_tables()`):

- Блоки с пересечением > 30% с известной таблицей помечаются как `"table"`
- Текстовые блоки с табличной структурой (строки с одинаковым числом колонок, разделённых пробелами/табуляцией) объединяются в таблицы
- Подписи к таблицам ("Table N...") привязываются к следующим таблицам

### Этап 5. Перевод блоков

Класс `TranslationPipeline` определяет какие блоки переводить.

**Блоки, пропускаемые при переводе:**

- `"figure"` -- изображения (не переводятся)
- `"table"` -- таблицы (переводятся отдельно через `generate()` LLM)
- `"empty"` -- пустые блоки
- `"metadata"` -- метаданные (авторы, журнал)
- `"reference"` -- список литературы
- `"reference_heading"` -- заголовок "References"

**Порядок перевода:**

1. Блоки группируются в секции по суммарному размеру (макс. 2500 символов)
2. Секции переводятся параллельно через `ThreadPoolExecutor`
3. Каждый блок внутри секции переводится последовательно с контекстом (предыдущий и следующий блоки)
4. Таблицы переводятся отдельно через `generate()` с промптом сохранения структуры

**Защита при переводе:**

- Академические цитаты `(Smith et al., 2015)` -> `[[CITE_0001]]`
- Ссылки `[1]`, `[N]` -> `[[REF0]]`
- DOI, URL, email -> защищённые токены
- После перевода токены восстанавливаются

**Валидация перевода:**

- Проверка на эхо (повтор оригинала)
- Проверка длины (не слишком короткий/длинный)
- Проверка на зацикливание (repetition ratio)
- Проверка сохранения чисел
- Проверка языка (кириллица для русского)

**Резервное копирование:** при ошибке основного переводчика используется fallback (Google -> OpenRouter -> llama).

## HTML-отчёт

- Тёмная и светлая темы
- Сворачиваемые блоки "Страница N"
- Содержание (TOC) по заголовкам
- Кнопки "Показать/Скрыть все оригиналы"
- Подсветка ссылок на литературу
- Таблицы рендерятся как HTML-таблицы, фигуры -- как изображения

## Батч-обработка
